# الدائرة المغلقة (Closed Circuit)

يحدد هذا المستند **نمط الدائرة المغلقة** - البنية الأساسية التي تضمن عدم وجود المستخدمين في حالة واجهة مستخدم غير صالحة.

---

## المشكلة

عندما ينقر المستخدم على "فتح Modal"، تنتقل آلة الحالة إلى `modalOpen` وتعرض Modal في فتحة `modal`. لكن إذا لم يصدر زر الإغلاق (X) في Modal حدثًا مرة أخرى إلى آلة الحالة، يكون المستخدم **عالقًا** - يمكنه رؤية Modal لكنه لا يمكنه إغلاقه.

هذه **دائرة مكسورة**.

---

## مبدأ الدائرة المغلقة

**يجب أن تكمل كل تفاعل واجهة المستخدم دائرة كاملة مرة أخرى إلى آلة الحالة.**

```
┌────────────────────────────────────────────────────────────────────────────┐
│                                                                            │
│   ┌─────────┐    ┌──────────┐    ┌─────────────┐    ┌──────────────────┐  │
│   │  حدث   │───►│  تقييم   │───►│   تنفيذ     │───►│  التأثيرات       │  │
│   │         │    │  الحارس  │    │  الانتقال   │    │  (render_ui)     │  │
│   └─────────┘    └──────────┘    └─────────────┘    └──────────────────┘  │
│        ▲                                                      │           │
│        │                                                      ▼           │
│   ┌─────────┐                                          ┌──────────────┐   │
│   │  ناقل   │◄─────────────────────────────────────────│   فتحة UI    │   │
│   │ الأحداث │         UI:CLOSE، UI:SAVE، إلخ           │   المعروضة   │   │
│   └─────────┘                                          └──────────────┘   │
│                                                                            │
└────────────────────────────────────────────────────────────────────────────┘
```

**القواعد:**

1. **جميع تفاعلات واجهة المستخدم تصدر أحداثًا عبر ناقل الأحداث** - لا تستخدم أبدًا استدعاءات داخلية مثل `onClick={() => setOpen(false)}`
2. **جميع الأحداث يجب أن يكون لها انتقالات مقابلة** - إذا أصدر المكون `UI:CLOSE`، يجب أن يكون هناك انتقال يتعامل مع `CLOSE`
3. **الفتحات غير الرئيسية يجب أن تعود إلى main** - إذا قمت بالعرض إلى فتحة `modal` أو `drawer` أو فتحات التداخل الأخرى، يجب أن يكون هناك انتقال يعرض مرة أخرى إلى فتحة `main`

---

## هرمية الفتحات ومتطلبات العودة

| الفتحة | النوع | متطلب العودة |
|--------|------|--------------|
| `main` | أساسي | لا يوجد - هذه هي القاعدة الرئيسية |
| `sidebar` | ثانوي | اختياري - يمكن التعايش مع main |
| `center` | ثانوي | اختياري - يمكن التعايش مع main |
| `modal` | تداخل | **مطلوب** - يجب أن يكون لدى انتقال CLOSE/CANCEL للعودة إلى main |
| `drawer` | تداخل | **مطلوب** - يجب أن يكون لدى انتقال CLOSE/CANCEL للعودة إلى main |
| `toast` | إشعار | يُغلق تلقائيًا، لا يحتاج انتقال |

**فتحات التداخل (`modal`، `drawer`) تحجب** - تمنع التفاعل مع المحتوى الرئيسي. يجب أن يكون المستخدمون قادرين على الخروج منها.

---

## عقود أحداث المكونات

المكونات التي يمكنها تشغيل انتقالات الحالة يجب أن تصدر أحداثًا عبر ناقل الأحداث:

### المكونات مع خاصية `actions` (مستوى الصفحة)

| المكون | الخاصية | تصدر |
|--------|---------|------|
| `page-header` | `actions` | `UI:{event}` لكل إجراء |
| `form` | `actions` | `UI:SAVE`، `UI:CANCEL` |
| `toolbar` | `actions` | `UI:{event}` لكل إجراء |

### المكونات مع خاصية `itemActions` (مستوى الصف)

| المكون | الخاصية | تصدر |
|--------|---------|------|
| `entity-table` | `itemActions` | `UI:{event}` مع حمولة `{ row }` |
| `entity-list` | `itemActions` | `UI:{event}` مع حمولة `{ row }` |
| `entity-cards` | `itemActions` | `UI:{event}` مع حمولة `{ row }` |

### مكونات التداخل (يجب أن تصدر أحداث إغلاق)

| المكون | محفز الإغلاق | يجب أن يصدر |
|--------|--------------|-------------|
| `modal` | زر X، Escape، نقر الطبقة | `UI:CLOSE` |
| `drawer` | زر X، Escape، نقر الطبقة | `UI:CLOSE` |
| `confirm-dialog` | زر Cancel | `UI:CANCEL` |
| `game-pause-overlay` | زر Resume | `UI:RESUME` |
| `game-over-screen` | زر Restart | `UI:RESTART` |

## متطلبات التحقق

يُنفذ المُحقق ما يلي:

### 1. اكتشاف الحدث اليتيم

إذا حدد `actions` أو `itemActions` للمكون حدثًا، يجب أن يكون هناك انتقال يتعامل معه.

```json
// سيء - OPEN_MODAL ليس له معالج
{
  "type": "page-header",
  "actions": [{ "label": "فتح", "event": "OPEN_MODAL" }]
}
// لكن لا يوجد انتقال: { "event": "OPEN_MODAL", ... }
```

**الخطأ**: `CIRCUIT_ORPHAN_EVENT: الإجراء 'فتح' يصدر حدث 'OPEN_MODAL' الذي ليس له معالج انتقال`

### 2. انتقال خروج Modal/Drawer

إذا قام انتقال بالعرض إلى فتحة `modal` أو `drawer`، يجب أن يكون هناك انتقال من الحالة المستهدفة الذي:
- يتعامل مع `CLOSE` أو `CANCEL` أو حدث مطلوب بالنمط (مثل `SAVE`)
- يعرض مرة أخرى إلى فتحة `main` (أو ينتقل إلى حالة تفعل ذلك)

```json
// سيء - حالة modalOpen ليس لها مخرج
{
  "from": "viewing",
  "event": "OPEN_MODAL",
  "to": "modalOpen",
  "effects": [["render-ui", "modal", { "type": "modal", ... }]]
}
// لكن لا يوجد انتقال: { "from": "modalOpen", "event": "CLOSE", ... }
```

**الخطأ**: `CIRCUIT_NO_EXIT: الحالة 'modalOpen' تعرض إلى فتحة 'modal' لكن ليس لها انتقال CLOSE/CANCEL. سيظل المستخدمون عالقين.`

### 3. متطلب العودة إلى Main

يجب أن تعود الحالات التي تعرض فقط إلى فتحات غير main في النهاية إلى حالة تعرض إلى فتحة `main`.

```json
// سيء - modalOpen يعرض فقط إلى modal، لا يعود أبدًا إلى main
{
  "from": "modalOpen",
  "event": "CLOSE",
  "to": "modalOpen",  // يعود إلى نفسها!
  "effects": []       // ولا يعرض شيئًا
}
```

**الخطأ**: `CIRCUIT_NO_MAIN_RETURN: الحالة 'modalOpen' ليس لها مسار للعودة إلى حالة تعرض إلى فتحة 'main'`

## متطلبات المترجم

يضمن المترجم الدوائر المغلقة من خلال:

### 1. أغلفة الفتحات للتداخلات

يتم تغليف فتحات التداخل في مكونات أغلفة فتحات تتعامل مع تواصل ناقل الأحداث:

| الفتحة | الغلاف | الأحداث المصدرة |
|--------|--------|-----------------|
| `modal` | `ModalSlot` | `UI:CLOSE`، `UI:CANCEL` |
| `drawer` | `DrawerSlot` | `UI:CLOSE`، `UI:CANCEL` |
| `toast` | `ToastSlot` | `UI:DISMISS`، `UI:CLOSE` |

مكونات الأغلفة:
- تظهر تلقائيًا عندما يكون هناك محتوى
- تتعامل مع محفزات الإغلاق/التجاهل (زر X، Escape، نقر الطبقة)
- تصدر أحداثًا عبر ناقل الأحداث حتى تتمكن آلة الحالة من الانتقال

**مثال**: `ModalSlot` تُغلف أي محتوى يُعرض إلى فتحة modal وتصدر `UI:CLOSE` عند الإغلاق:

```typescript
// ModalSlot.tsx
const handleClose = () => {
  eventBus.emit('UI:CLOSE');
  eventBus.emit('UI:CANCEL');
};

return (
  <Modal isOpen={Boolean(children)} onClose={handleClose}>
    {children}
  </Modal>
);
```

### 2. توليد خاصية `event`، ليس `onClick`

بالنسبة للإجراءات في `page-header` و `form` وما إلى ذلك، يولد المترجم خاصية `event` حتى يصدر المكون عبر ناقل الأحداث:

```typescript
// الكود المولد:
<PageHeader actions={[{ label: "فتح", event: "OPEN_MODAL" }]} />

// ليس:
<PageHeader actions={[{ label: "فتح", onClick: () => dispatch('OPEN_MODAL') }]} />
```

يتعامل المكون مع إصدار `UI:OPEN_MODAL` عبر ناقل الأحداث، والذي يلتقطه `useUIEvents` ويوجهه.

### 3. يجب على الصفحة عرض جميع الفتحات مع الأغلفة

الصفحات المولدة تعرض جميع الفتحات، مع تغليف فتحات التداخل في أغلفة الفتحات:

```typescript
// الصفحة المولدة:
return (
  <>
    <VStack>
      {/* فتحات المحتوى - معروضة مباشرة */}
      {ui?.main}
      {ui?.sidebar}
      {ui?.center}
    </VStack>
    {/* فتحات التداخل - مُغلفة للدائرة المغلقة */}
    <ModalSlot>{ui?.modal}</ModalSlot>
    <DrawerSlot>{ui?.drawer}</DrawerSlot>
    <ToastSlot>{ui?.toast}</ToastSlot>
  </>
);
```

**المفتاح**: أغلفة الفتحات تصدر أحداثًا عبر ناقل الأحداث عند إغلاق/تجاهل الطبقة. هذا يكمل الدائرة مرة أخرى إلى آلة الحالة.

## نمط المخطط للـ Modal

نمط المخطط الصحيح للـ modal:

```json
{
  "states": [
    { "name": "viewing", "isInitial": true },
    { "name": "modalOpen" }
  ],
  "events": [
    { "key": "OPEN_MODAL", "name": "فتح Modal" },
    { "key": "CLOSE", "name": "إغلاق" }
  ],
  "transitions": [
    {
      "from": "viewing",
      "event": "INIT",
      "to": "viewing",
      "effects": [
        ["render-ui", "main", {
          "type": "page-header",
          "title": "مثال",
          "actions": [{ "label": "فتح Modal", "event": "OPEN_MODAL" }]
        }]
      ]
    },
    {
      "from": "viewing",
      "event": "OPEN_MODAL",
      "to": "modalOpen",
      "effects": [
        ["render-ui", "modal", { "type": "modal", "title": "Modal" }]
      ]
    },
    {
      "from": "modalOpen",
      "event": "CLOSE",
      "to": "viewing",
      "effects": [
        ["render-ui", "main", {
          "type": "page-header",
          "title": "مثال",
          "actions": [{ "label": "فتح Modal", "event": "OPEN_MODAL" }]
        }]
      ]
    }
  ]
}
```

**النقاط الرئيسية:**
1. انتقال `OPEN_MODAL` يعرض إلى فتحة `modal`
2. انتقال `CLOSE` من `modalOpen` يعرض مرة أخرى إلى فتحة `main`
3. كلا الحدثين لهما انتقالات مقابلة

---

## ملخص

يضمن نمط الدائرة المغلقة:

1. **لا يكون المستخدمون عالقين أبدًا** - كل حالة واجهة مستخدم لها مسار خروج
2. **تتدفق الأحداث عبر آلة الحالة** - لا إدارة حالة داخلية تتجاوز الدائرة
3. **تعود فتحات التداخل إلى main** - Modals والـ drawers دائمًا لها انتقالات إغلاق
4. **يكتشف التحقق الكسور** - يتحقق المترجم من اكتمال الدائرة قبل توليد الكود

عندما تكون الدائرة مكسورة، يواجه المستخدمون أزرارًا "ميتة" و Modals عالقة وواجهة مستخدم غير مستجيبة. يعمل المُحقق والمترجم معًا لمنع هذا.
