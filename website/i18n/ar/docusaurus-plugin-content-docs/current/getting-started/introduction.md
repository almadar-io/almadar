# مقدمة إلى المدار

> **فيزياء البرمجيات**: لغة طبيعية → مخطط → تطبيق إنتاج

## ما هو المدار؟

المدار (Almadar) هو **لغة برمجة تصريحية** لبناء تطبيقات متكاملة. بدلاً من كتابة كود إلزامي متناثر عبر الواجهة الأمامية والخلفية، تصرّح بتطبيقك كمخطط من:

- **الكيانات** - هياكل البيانات مع قواعد الاستمرار
- **السمات** - السلوك المعرّف كآلات حالة
- **الصفحات** - المسارات مع ربط الواجهة

مترجم المدار يحوّل هذا المخطط إلى تطبيق كامل جاهز للإنتاج.

## المشكلة التي يحلها المدار

### التطوير التقليدي

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  فريق الواجهة   │     │  فريق الخادم    │     │  فريق البيانات │
│    الأمامية     │     │                 │     │                 │
├─────────────────┤     ├─────────────────┤     ├─────────────────┤
│ • React كود     │     │ • Express كود   │     │ • SQL Schemas   │
│ • صلاحيات UI    │     │ • صلاحيات API   │     │ • صلاحيات DB    │
│ • اختبارات      │     │ • اختبارات      │     │ • اختبارات      │
│   وحدة           │     │   تكامل         │     │   بيانات        │
└─────────────────┘     └─────────────────┘     └─────────────────┘
```

**المشاكل:**
- منطق الأعمال مكرر عبر الطبقات
- الصلاحيات متناثرة في الوسيط والمسارات والاستعلامات
- التوثيق منفصل عن الكود
- الاختبار يتطلب عدة مناهج

### التطوير بالمدار

```
┌─────────────────────────┐
│       schema.orb        │
│  (مصدر الحقيقة الوحيد)  │
└───────────┬─────────────┘
            │
            │ orbital compile
            │
            ▼
┌───────────────────────────────────────────────┐
│         تطبيق متكامل                          │
├───────────────────────────────────────────────┤
│ • واجهة React                                 │
│ • خادم Express                                │
│ • نماذج قاعدة البيانات                        │
│ • صلاحيات (في Guards)                         │
│ • توثيق (من المخطط)                           │
└───────────────────────────────────────────────┘
```

**الفوائد:**
- مصدر حقيقة واحد
- الصلاحيات في الحراس (مكان واحد)
- المخطط هو التوثيق
- آلات الحالة قابلة للاختبار بطبيعتها

## المفاهيم الأساسية

### 1. الكيانات

الكيانات تعرّف هياكل البيانات:

```json
{
  "name": "Task",
  "collection": "tasks",
  "persistence": "persistent",
  "fields": [
    { "name": "title", "type": "string", "required": true },
    { "name": "status", "type": "enum", "values": ["pending", "in_progress", "completed"] },
    { "name": "assignee", "type": "relation", "relation": { "entity": "User" } },
    { "name": "dueDate", "type": "date" }
  ]
}
```

**أنواع الاستمرار:**
- `persistent` - محفوظة في قاعدة البيانات
- `runtime` - في الذاكرة (خاصة بالجلسة)
- `singleton` - نسخة عامة واحدة

### 2. السمات

السمات تعرّف السلوك كآلات حالة:

```json
{
  "name": "TaskLifecycle",
  "linkedEntity": "Task",
  "stateMachine": {
    "states": [
      { "name": "Pending", "isInitial": true },
      { "name": "InProgress" },
      { "name": "Done" }
    ],
    "events": ["START", "COMPLETE"],
    "transitions": [
      {
        "from": "Pending",
        "to": "InProgress",
        "event": "START",
        "guard": ["eq", ["@entity.assignee", "@payload.userId"]],
        "effects": [
          ["set", "status", "in_progress"],
          ["persist", "update", "Task", "@entity.id"],
          ["render-ui", "main", { "type": "task-detail", "entity": "Task" }]
        ]
      }
    ]
  }
}
```

**الفكرة الأساسية:** السمة تجمع بين السلوك (آلة الحالة) والواجهة (تأثيرات render-ui).

### 3. التعابير S

كل المنطق يُعبَّر عنه كمصفوفات:

**الحراس:**
```json
["and",
  ["eq", ["@entity.status", "pending"]],
  ["eq", ["@entity.assignee", "@payload.userId"]]
]
```

**التأثيرات:**
```json
[
  ["set", "status", "completed"],
  ["persist", "update", "Task", "@entity.id"],
  ["emit", "TASK_COMPLETED"],
  ["render-ui", "main", { "type": "success-message" }]
]
```

### 4. الدائرة المغلقة

```
1. حدث → المستخدم ينقر "أكمل المهمة"
   ↓
2. حارس → فحص: هل المستخدم هو المكلف؟
   ↓
3. انتقال → الحالة: قيد التنفيذ → منجز
   ↓
4. تأثيرات → الخادم: حفظ في قاعدة البيانات
               العميل: عرض رسالة، تحديث القائمة
   ↓
5. استجابة → الواجهة تتحدث بالبيانات الحقيقية
```

كل تفاعل مستخدم يتبع هذا المسار - لا توجد استدعاءات API مخصصة أو معالجات منفصلة.

## لماذا "المدار"؟

المدار يعني "Orbit" بالإنجليزية. اخترنا هذا الاسم لأن التطبيقات المبنية بالمدار تتبع نفس المبادئ التي تحكم الفيزياء:

| الفيزياء | المدار |
|----------|--------|
| الأجسام في الفضاء لها خصائص | الكيانات (البيانات) لها حقول |
| القوى تسبب الحركة | الأحداث تشغّل السلوك |
| القوانين تحكم الحركة | الحراس تتحكم في الانتقالات |
| ردود الفعل | التأثيرات |
| المدارات المستقرة | حالات التطبيق الصالحة |

## ما ستبنيه

بنهاية هذا الدليل، ستتمكن من:

1. **تصميم مخططات** - تعريف الكيانات والسمات والصفحات
2. **كتابة حراس** - التحكم في من يمكنه فعل ماذا
3. **إنشاء تأثيرات** - تنسيق العمليات عبر العميل والخادم وقاعدة البيانات
4. **ربط المدارات** - جعل السمات تتواصل عبر الأحداث
5. **نشر التطبيقات** - تحويل المخططات إلى أنظمة إنتاجية
