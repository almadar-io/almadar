ماذا لو كان JSON يستطيع التعبير عن المنطق، لا البيانات فقط؟ ماذا لو كانت ملفات الإعداد الخاصة بك تستطيع اتخاذ القرارات؟

بنينا لغة برمجة كاملة تورنغ هي مجموعة فرعية صارمة من JSON. لا صياغة جديدة. لا محلل مخصص. كل برنامج من المدار هو JSON صالح.

إليك لماذا — وكيف.

## مشكلة لغات الإعداد

الصناعة تدور حول هذه المشكلة منذ عقود:

- **YAML** — رائعة للبيانات، كارثية للمنطق. تؤدي إلى كوابيس القوالب (ننظر إليك، Helm charts).
- **HCL (Terraform)** — اخترعت صياغة جديدة. الآن تحتاج محللًا، و LSP، وإضافات محرر، وتدريبًا.
- **Dhall** — مبدئية لكن متخصصة. قلة من المطورين يعرفون بوجودها.
- **Jsonnet/CUE** — تشبه JSON لكنها ليست JSON. قريبة، لكنها تكسر توافق الأدوات.

النمط: كل مرة يحتاج شخص منطقًا في الإعداد، يخترع لغة جديدة. محلل جديد. أدوات جديدة. منحنى تعلم جديد.

سألنا: **ماذا لو لم نفعل ذلك؟**

## البصيرة: التعبيرات-S هي بالفعل JSON

في عام 1958، اخترع جون مكارثي التعبيرات-S لـ Lisp:

```lisp
(+ 1 2)
(if (> x 10) "big" "small")
```

التعبيرات-S هي مجرد قوائم متداخلة مع دالة في الموضع الأول.

مصفوفات JSON هي... قوائم متداخلة.

```json
["+", 1, 2]
["if", [">", "x", 10], "big", "small"]
```

**التعبيرات-S *هي* مصفوفات JSON.** لم نكن بحاجة لاختراع صياغة. كنا بحاجة لتفسير ما كان موجودًا بالفعل.

## كيف يعمل المدار

برنامج المدار هو كائن JSON يحتوي على كيانات، وآلات حالة، ومنطق مُعبَّر عنه بتعبيرات-S:

```json
{
  "name": "ApprovalWorkflow",
  "orbitals": [{
    "entity": {
      "name": "Request",
      "fields": [
        { "name": "amount", "type": "number" },
        { "name": "status", "type": "enum", "values": ["pending", "approved", "rejected"] }
      ]
    },
    "traits": [{
      "name": "ApprovalTrait",
      "linkedEntity": "Request",
      "stateMachine": {
        "states": [
          { "name": "Pending", "isInitial": true },
          { "name": "Approved" },
          { "name": "Rejected" }
        ],
        "transitions": [{
          "from": "Pending",
          "to": "Approved",
          "event": "APPROVE",
          "guard": ["and",
            [">=", "@user.roleLevel", 3],
            ["<", "@entity.amount", 10000]
          ],
          "effects": [
            ["set", "@entity.status", "approved"],
            ["set", "@entity.approvedAt", "@now"],
            ["emit", "REQUEST_APPROVED"]
          ]
        }]
      }
    }]
  }]
}
```

المنطق (الحارس، التأثيرات) هو تعبيرات-S صرفة. البنية (الكيانات، الحالات، الانتقالات) هي JSON صرف. معًا، يُشكّلان برنامجًا كاملًا.

## لماذا هذا مهم: التماثل الأيقوني

التماثل الأيقوني (Homoiconicity) يعني "الكود والبيانات يتشاركان نفس التمثيل." إنها القوة الخارقة لـ Lisp، والآن هي قوة JSON.

لأن برامج المدار هي JSON:

**1. كل أداة JSON تعمل على برامج المدار.**

```bash
# Validate with any JSON validator
cat app.orb | python -m json.tool

# Query with jq
jq '.orbitals[].traits[].stateMachine.states' app.orb

# Diff two schemas
diff <(jq -S . v1.orb) <(jq -S . v2.orb)
```

**2. الذكاء الاصطناعي يستطيع توليد البرامج وتعديلها.**

نماذج اللغة الكبيرة (LLMs) ممتازة في توليد JSON مُهيكل. وهي سيئة في توليد صياغة صحيحة في لغات جديدة. بالبقاء في JSON، يمكن لأي نموذج يستطيع إنتاج JSON صالح — وهو كلها — توليد برامج المدار بسهولة.

**3. البرامج هي بيانات يمكنك تحويلها.**

تريد إضافة تسجيل مراجعة لكل انتقال؟ اكتب تحويل JSON:

```javascript
schema.orbitals.forEach(orbital =>
  orbital.traits.forEach(trait =>
    trait.stateMachine.transitions.forEach(t => {
      t.effects.push(["log", "info", `Transition: ${t.from} → ${t.to}`]);
    })
  )
);
```

لا تحليل شجرة صياغة مجردة (AST). لا إضافات مُصرِّف. مجرد معالجة بيانات.

## حجة اكتمال تورنغ

اللغة تكون كاملة تورنغ إذا استطاعت محاكاة أي حساب. المدار يحقق ذلك من خلال:

1. **آلات الحالة** — حالة عشوائية، انتقالات، وذاكرة (حقول الكيان)
2. **حرّاس التعبيرات-S** — منطق بولياني مع تداخل عشوائي (`and`، `or`، `not`، عوامل المقارنة)
3. **تأثيرات التعبيرات-S** — تأثيرات جانبية تشمل `set` (كتابة الذاكرة)، `emit` (الاتصال)، و `if` (التفرع)
4. **أحداث عبر المدارات** — اتصال بين العمليات (emit/listen)
5. **التكرار عبر الانتقالات الذاتية** — يمكن للحالة أن تنتقل إلى نفسها مع تعديل حقول الكيان

حلقة ذاتية مع تأثيرات شرطية وتحديثات حقول الكيان تعادل حلقة while مع حالة قابلة للتغيير:

```json
{
  "from": "Computing",
  "to": "Computing",
  "event": "TICK",
  "guard": [">", "@entity.counter", 0],
  "effects": [
    ["set", "@entity.counter", ["-", "@entity.counter", 1]],
    ["set", "@entity.result", ["+", "@entity.result", "@entity.counter"]],
    ["emit", "TICK"]
  ]
}
```

هذا يحسب مجموع الأرقام من N إلى 0. آلة الحالة هي الحلقة. الكيان هو الذاكرة. الحارس هو شرط الإنهاء.

## المقارنة: مشهد لغات الإعداد

| اللغة | متوافقة مع JSON | دعم المنطق | كاملة تورنغ | الأدوات |
|----------|----------------|---------------|-----------------|---------|
| JSON | نعم | لا | لا | عالمية |
| YAML | لا | لا | لا | واسعة |
| Jsonnet | جزئيًا | نعم | نعم | محدودة |
| Dhall | لا | نعم | لا (عمدًا) | ضئيلة |
| CUE | جزئيًا | نعم | لا (عمدًا) | متنامية |
| HCL | لا | محدود | لا | Terraform |
| **المدار** | **نعم** | **نعم** | **نعم** | **عالمية (JSON)** |

المدار هو اللغة الوحيدة الكاملة تورنغ التي هي مجموعة فرعية صارمة من JSON. هذا يعني أن كل أداة JSON، وكل واجهة JSON برمجية، وكل قاعدة بيانات JSON، وكل نموذج لغوي كبير يفهم JSON يعمل مع برامج المدار فورًا.

## كيف تُنفَّذ التعبيرات-S

مُصرِّف المدار يُقيّم التعبيرات-S بشكل تكراري:

```
["and",
  [">=", "@user.roleLevel", 3],
  ["<", "@entity.amount", 10000]
]
```

**خطوات التقييم:**

1. حل الروابط: `@user.roleLevel` → `5`، `@entity.amount` → `7500`
2. تقييم التعبيرات الداخلية: `[">=", 5, 3]` → `true`، `["<", 7500, 10000]` → `true`
3. تقييم التعبير الخارجي: `["and", true, true]` → `true`

المُصرِّف يُحسّن تقييمات الحرّاس المتكررة داخليًا — وهو شائع في واجهات المستخدم حيث يُتحقق من نفس الشروط في كل عرض — لذا التقييم سريع حتى للتعبيرات المعقدة.

## التوسع بدون تعيين إصدارات

إضافة عوامل جديدة إلى المدار لا تتطلب تحديث إصدار المخطط:

```json
["geo-distance", "@entity.location", "@payload.target"]
```

إذا كان المُقيّم يعرف `geo-distance`، يُقيّمه. إن لم يعرفه، يُرجع خطأ برسالة واضحة. العوامل الجديدة **إضافية** — لا تكسر البرامج الموجودة أبدًا.

هذا هو نفس نموذج التوسع الذي جعل Lisp تبقى لمدة 65 عامًا.

## المقايضة: الإسهاب

لنكن صريحين. التعبيرات-S في JSON أكثر إسهابًا مما ستكون عليه صياغة مخصصة:

```
-- Hypothetical custom syntax
guard: user.roleLevel >= 3 and entity.amount < 10000

-- Almadar (actual)
"guard": ["and", [">=", "@user.roleLevel", 3], ["<", "@entity.amount", 10000]]
```

الصياغة المخصصة 50 حرفًا. نسخة المدار 75. هذا ~50% أكثر حروفًا.

نعتقد أن هذه المقايضة تستحق لأن:
- لن تحتاج أبدًا لمحلل مخصص
- لن تحتاج أبدًا لـ LSP مخصص
- لن تحتاج أبدًا لتعليم فريقك صياغة جديدة
- الذكاء الاصطناعي يُولّدها بشكل صحيح من المحاولة الأولى
- كل أداة JSON في الوجود تعمل على برامجك

الإسهاب تكلفة لمرة واحدة. توافق الأدوات إلى الأبد.

## الخلاصة

كل عقد، يخترع شخص لغة إعداد جديدة لحل مشكلة "المنطق في الإعداد". كل واحدة تضيف محللًا، ومنحنى تعلم، ومنظومة لصيانتها.

المدار يسلك طريقًا مختلفًا: **لا صياغة جديدة**. مجرد مصفوفات JSON تُفسَّر كتعبيرات-S، مُدمجة مع آلات الحالة لتدفق التحكم والكيانات للذاكرة.

النتيجة هي لغة كاملة تورنغ:
- تفهمها كل أداة JSON
- يستطيع كل نموذج لغوي كبير توليدها
- يستطيع كل مطور قراءتها (إنها مجرد مصفوفات)
- تُصرَّف إلى TypeScript و Rust و Python

لأن أفضل صياغة قد تكون تلك التي تعرفها بالفعل.

استكشف [مكتبة التعبيرات-S القياسية](/docs/stdlib) لرؤية جميع العوامل المتاحة.
